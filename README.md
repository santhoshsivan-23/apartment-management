# Apartment Management System — Fully Offline Edition

A Flutter app for managing a residential community (buildings, apartments,
residents, maintenance bills, payments, expenses, complaints, visitors,
amenities, notices, vendors, staff, assets, documents, reports) that works
**entirely offline**. There is no backend, no REST API, and no network
permission required at runtime — every screen reads and writes to a local
SQLite database on the device.

## Architecture

```
Flutter UI (screens)
      ↓
Provider-free state (StatefulWidget, local setState)
      ↓
Repository (BaseRepository — generic CRUD over sqflite)
      ↓
SQLite (sqflite package)
      ↓
Local device storage (app documents directory)
```

Rather than hand-writing near-identical CRUD code for 25+ tables, most
feature screens are thin configuration files built on top of two reusable
pieces in `lib/core/widgets/`:

- **`BaseRepository`** (`lib/core/repository/base_repository.dart`) — generic
  insert / update / delete / getAll / count / sum / rawQuery over any table.
- **`GenericCrudScreen`** (`lib/core/widgets/generic_crud_screen.dart`) — a
  searchable list + add/edit form + delete, driven entirely by a list of
  `FieldConfig` describing each column (text, number, date picker, or a
  dropdown backed by another table, e.g. picking a Resident's Apartment).

Modules that need real business logic instead of plain CRUD — maintenance
bill generation, payments, reports, backup/restore, documents — have their
own hand-written screens (see `lib/features/maintenance`, `lib/features/reports`,
`lib/features/backup_restore`, `lib/features/documents`).

## Data layer

`lib/core/database/app_database.dart` creates every table from the schema
below on first launch (`sqflite`, stored in the app's documents directory)
and seeds a few default lookup rows (roles, maintenance/expense categories).

```
communities, buildings, floors, apartments
residents, family_members, vehicles, parking_slots
maintenance_categories, maintenance_bills, bill_items, payments
expenses, expense_categories
complaints, complaint_comments
visitors, visitor_passes
amenities, facility_bookings
notices, events
vendors, vendor_payments
staff, staff_attendance
assets, asset_maintenance
documents
users, roles, audit_logs
```

Every write also appends a row to `audit_logs` (who/what/when), fully local.

## Offline-only guarantees

- **Auth**: a local PIN, hashed with SHA-256 and stored in
  `shared_preferences` (`lib/core/services/auth_service.dart`). No accounts,
  no server.
- **Documents**: `file_picker` lets the user attach files that already exist
  on the device; only the local file path is stored — nothing is uploaded.
- **Backup/Restore**: `lib/core/services/backup_service.dart` copies the
  actual `.db` file to a `backups/` folder in app storage, and can restore by
  copying a chosen `.db` file back over the live database. `share_plus` is
  used only so the user can move that file to their own storage (e.g. Drive,
  email) — the app itself never talks to any server.
- **Reports**: computed with local SQL aggregates (`SUM`, `COUNT`, `GROUP BY`)
  against the on-device database, charted with `fl_chart`.

## Getting started

This deliverable contains the `lib/`, `assets/`, `test/`, and `pubspec.yaml`
for the app. Platform folders (`android/`, `ios/`, `web/`, etc.) are
generated by the Flutter tool itself and aren't included here, since they're
machine/version-specific. To run it:

```bash
# 1. Create a fresh Flutter project shell (generates android/ios/web/etc.)
flutter create apartment_management_app
cd apartment_management_app

# 2. Copy this project's lib/, assets/, test/ and pubspec.yaml over the
#    generated ones (overwrite when prompted).

# 3. Fetch packages
flutter pub get

# 4. Run
flutter run
```

First launch asks you to set a local PIN, then drops you into the Dashboard.
Use the **Modules** tab to reach every feature (Community, Buildings,
Apartments, Residents, Maintenance Bills, Payments, Expenses, Complaints,
Visitors, Parking, Amenities, Facility Bookings, Notices, Events, Vendors,
Vendor Payments, Staff, Staff Attendance, Assets, Asset Maintenance, Reports,
Documents, Backup & Restore, Settings).

## Extending it

To add a brand-new table-backed module, you generally only need to:

1. Add a `CREATE TABLE` in `app_database.dart`.
2. Add a screen file with a `GenericCrudScreen(tableName: ..., fields: [...])`.
3. Add a tile for it in `lib/features/home/home_screen.dart`.

That's the same pattern every existing module (Vendors, Staff, Assets, etc.)
already follows.
